# 与板块三、四确认的清单

用途：把接口与验收条件定下来后再写最终 KEDA/选主部署配置。不以勾选清单代替实测；本文件不触发部署。

## 板块三：HPA 与缓存

- [ ] 提供可重复运行的 k6/JMeter 等脚本和依赖版本；指定代码提交。
- [ ] 接口路径、读/写方法、角色、测试账号、业务成功断言；不压健康检查代替业务。
- [ ] 业务 Owner 批准测试数据和写入副作用；测试记录有唯一标识、清理方式。
- [ ] 并发/到达率、阶梯、持续时间、p95/错误率目标和停止阈值；区分未发出的请求。
- [ ] CPU HPA 是否适合该场景；提供主要瓶颈假设，不保证施压必触发 CPU 阈值。
- [ ] 缓存开关的准确配置名、默认值、TTL、命中/未命中观察方法、更新与失效规则。
- [ ] 缓存开/关对比固定数据集和负载，明确冷缓存/预热阶段；同时记录 DB 查询量和业务正确性。
- [ ] Read Replica 路由由谁实现，哪些查询可容忍复制延迟；不能把 `readOnly=true` 当作已路由到副本。
- [ ] 汇总按阶段给出：负载、实际请求、成功/失败、p95、缓存命中、DB 查询量；确认报告由谁展示。

## 板块四：report-worker / KEDA

- [ ] API 和 Worker 是否使用同镜像不同启动参数/Profile？给出准确命令和配置名。
- [ ] API 保持至少 2 副本；Worker 独立 Deployment，才允许缩至 0。
- [ ] “报告生成任务队列”和当前“领域事件事实队列”是否不同；不要把同一事件队列分给不兼容消费者竞争消息。
- [ ] 消息 schema、版本、唯一 task ID、业务去重键、测试消息生成方法。
- [ ] 任务何时入队：谁调度、时区、批量任务如何拆分；从 `@Scheduled` 迁移时如何避免双重触发。
- [ ] 单任务最长耗时、每 Pod 并发、SQS visibility timeout、续期、何时删除消息。
- [ ] 失败重试次数、DLQ、幂等、处理中 Pod 终止后的重投/重复执行行为。
- [ ] LLM mock 固定时延、限流与失败回退，真实模型调用的费用/配额；未经同意不跑真实批量调用。
- [ ] Queue URL/区域、Worker 和 KEDA 各自需要的限定 IAM 身份；凭据不用静态密钥写入 values。
- [ ] KEDA polling/cooldown、每副本目标积压、max replicas、in-flight 是否计入伸缩指标，与并发/容量一致。
- [ ] 谁记录可见/in-flight/DLQ 数、Pod 数、完成/重复/失败任务、等待/处理耗时。
- [ ] 验收必须同时证明 0→N→0 和任务正确完成，不能只看 Pod 曲线。

## 板块四：Active-Standby

- [ ] 选定服务和场景，确认按 Proposal 的“只有 Active 接流量并执行任务”验收，还是仅任务互斥；若变更承诺需团队明确记录。
- [ ] 选主使用什么机制；ShedLock 只能证明特定任务互斥，不自动证明固定 Leader/Standby。
- [ ] 查询当前 Active/Standby 的日志/指标/状态接口、Pod identity、选举 epoch/任期。
- [ ] 心跳、失效判定、接管阈值、与约 30 秒目标的关系。
- [ ] Standby readiness=false，但 liveness 保持健康；Active 丢领导权后如何停止接单/执行。
- [ ] 防止双主和重复副作用：租约失效后的停止/隔离、事务/幂等或 fencing 方案，不能只靠删除 Pod 演示。
- [ ] 如果采用 Kubernetes Lease，先给出 Lease 名称/namespace、确切 verbs，板块二再准备最小 RBAC；本次不预先授权。
- [ ] 与 HPA/PDB/滚动更新如何共存；备用不 Ready 可能使 `maxUnavailable=0` 的滚动发布持续等待，必须先验证。
- [ ] 确认故障注入只针对已识别 Active Pod，不重复演练 EC2/RDS/Redis，也不删除共享环境。
- [ ] 记录故障请求、旧 Active 停止、备用接管、请求恢复、任务 ID/去重结果，明确人工触发与自动恢复。
- [ ] 模式切换和回退如何走现有 CD，保留当前网址和正常 Active-Active 部署能力。

## 会前共同确认

- [ ] 指定负责人：板块二云端操作/采集；板块三负载/性能；板块四任务和选主正确性。
- [ ] 指定停止条件、谁有权停止负载、恢复步骤、费用范围。
- [ ] 测试数据、账号与证据分享范围；Cookie/Secret 不进入仓库或证据包。
- [ ] 最终谁讲哪张图；将实测、配置能力和未完成项分开。
